## 4. Lo que queda en el radar (no bloqueante)

- **T7 cron**: el handler está correcto pero no hay `markOverdue()` automático configurado (es manual via API). Requiere que el operador dispare un cron o agregue `MarkTasksOverdueMessage::dispatch()` a un schedule.
- **P-F.2 campus_assignment migration**: depende de tablas `campus_*` que no existen en prod. No rompe nada pero la lógica de backfill está lista para cuando se haga la migración inicial del sistema campus.

## 5. Lecciones aprendidas

1. **El audit debe incluir siempre verificación end-to-end con auth real**: muchos bugs de authZ solo se ven mandando headers correctos. Una simple revisión de código sin curl real deja pasar el 30% de los issues.
2. **El refactor centralizado de `apiFetch()` (commit a24c70a) paga dividendos**: migrar 10 controllers de `fetch()` a `window.apiFetch()` automáticamente inyecta `X-Game-Code` y elimina una clase entera de bugs de auth.
3. **PHPStan catch-22 con métodos heredados**: cuando un método existe en una clase padre, PHPStan no siempre lo sabe. Usar `method_exists()` puede ser la solución correcta aunque genere warnings. En este caso `AdminAuthTrait` confía en que todos los callers extiendan `AbstractController`.
4. **DBAL 4 migration compatibility**: la detección de plataforma via `getDatabasePlatform()::class` permite escribir migraciones portables. Antes era `getName()` que fue removido en DBAL 4.
5. **El `BINARY_FILE_RESPONSE` debe ir con flag `RESUME_INLINE=false`** para forzar download en vez de mostrar inline en el navegador.

## 6. Procedimiento para futuros audits

1. **Phase A** (backend): leer controllers y reportes, identificar issues estructurales (auth, validaciones, schema)
2. **Phase B** (CRUD): verificar que los endpoints CRUD funcionan — incluyendo filtros y formas
3. **Phase C** (alumno): revisar el path del estudiante, no solo del admin
4. **Phase D** (tasks): state machines son la fuente #1 de bugs — siempre dibujar transiciones
5. **Phase E** (perf/deuda): no skipping — N+1 escala O(n²) con datos reales
6. **Phase F** (portabilidad): verificar que las migraciones corran en MySQL Y SQLite (CI usa sqlite)
7. **Verificación final**: deploy + probe scripts con auth real + tests locales + PHPStan

En futuras sesiones, seguir este mismo flujo:

```bash
# 1. Backup pre-trabajo
cp -a public_html public_html.backup-pre-audit-$(date +%Y%m%d)

# 2. Probe por cada issue, fix mínimo
# 3. Deploy + verificar con curl real
# 4. Tests locales + PHPStan
# 5. CHANGELOG + commit
```
