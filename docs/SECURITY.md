# TNSVT — Security Audit & Protocol

Generated by `/audit` on initial inspection. **Treat all findings as live until verified.**

This document is the source of truth for: which secrets exist, what to rotate, and the
operating rules for handling credentials in the TNSVT V2 repository.

> **Never commit, paste or share values from `.env*` files.** This document describes
> keys and categories — not values.

### `.env.local` — secret categories present

The file contains live credentials for:

- **MySQL database** (production-style `DATABASE_URL` with `user:password@host:port/db`)
- **JWT passphrase** (`JWT_PASSPHRASE`) — used to decrypt `config/jwt/private.pem`
- **Single admin password** (`ADMIN_PASSWORD`) — admin login credential
- **Firebase web config** (`FIREBASE_WEB_API_KEY`, `FIREBASE_PROJECT_ID`,
  `FIREBASE_AUTH_DOMAIN`, `FIREBASE_STORAGE_BUCKET`,
  `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_APP_ID`,
  `FIREBASE_WEB_PUSH_VAPID_KEY`) — these are *client-side* keys; web API key is
  restricted by Firebase Security Rules, but the project ID and VAPID key are still
  PII-adjacent.
- **Mercure JWT secret** (`MERCURE_JWT_SECRET`) — value still says
  `dev-secret-change-in-production!!`, i.e. **not actually rotated for prod**.
- **Legacy MySQL connection** (`LEGACY_DATABASE_URL`) — real credentials
- **Mail from address** (`APP_EMAIL_FROM`, `APP_EMAIL_FROM_NAME`) — not a secret but
  identity claim
- **Production URL** (`APP_SERVER_URL`) — not a secret but identifies deployment

### `.env` — committed secrets to be aware of

- Line 50: `JWT_PASSPHRASE=123ffa92…` — **appears to be a real passphrase, committed**.
  This is a leak. Rotate immediately (see §3).
- Lines 38–40: `JWT_SECRET_KEY`/`JWT_PUBLIC_KEY` paths only — not secrets themselves.

## 2. Configuration conflicts found

These are bugs, not secrets, but they must be fixed during security cleanup:

1. **Duplicate `JWT_PASSPHRASE` in `.env`** — defined twice (line 40 and line 50) with
   *different values*. Symfony uses the last one. `.env.local` overrides it. This is
   confusing and risky.
2. **`APP_SECRET` missing from `.env` and `.env.local`** — `.env.dev` has one but prod
   falls back to empty (line 19). Symfony will refuse to boot in some configurations;
   in others it will run with no signing secret, which is a session/CSRF risk.
3. **`MERCURE_JWT_SECRET`** still `dev-secret-change-in-production!!` — production
   Mercure hub would accept forged tokens.

## 3. Rotation protocol (must run before any external share)

> Do not run these commands until you are sure the file `.env.local` is no longer
> exposed to any public channel. The zip itself counts as exposure.

### Step 1 — Treat existing values as compromised

Even though `.env.local` is gitignored, the fact that it appeared in the zip means
*anyone who has the zip has these secrets*. Assume breach.

### Step 2 — Rotate, in this order

| Priority | What | Where |
|---|---|---|
| P0 | `ADMIN_PASSWORD` | Hostinger control panel / DB user management |
| P0 | `DATABASE_URL` (MySQL user password) | Hostinger → MySQL → user password |
| P0 | `JWT_PASSPHRASE` + regenerate keypair | `bin/console lexik:jwt:generate-keypair --overwrite` |
| P0 | `MERCURE_JWT_SECRET` | Mercure hub config; rotate and redeploy |
| P1 | `LEGACY_DATABASE_URL` (legacy MySQL password) | Legacy tnsvt.com DB |
| P1 | `FIREBASE_WEB_API_KEY` restrictions | Firebase Console → API key restrictions |
| P1 | Firebase `service-account.json` | Regenerate service account, replace file |
| P2 | `JWT_PASSPHRASE` value leaked in committed `.env` line 50 | After regen, that value is dead. Remove from `.env` in next commit. |

### Step 3 — Move to Symfony Secrets (recommended)

```bash
bin/console secrets:set DATABASE_URL
bin/console secrets:set JWT_PASSPHRASE
bin/console secrets:set ADMIN_PASSWORD
bin/console secrets:set MERCURE_JWT_SECRET
bin/console secrets:set FIREBASE_WEB_API_KEY
# etc.
```

After this, the values live in `config/secrets/{env}/{env}.decrypt.private.php`
(which IS in `.gitignore`) and `.env.local` only holds `APP_SECRET` + `LOCK_HASH`.

### Step 4 — Remove leaked passphrase from `.env`

Once the keypair is regenerated and `.env.local` holds the new passphrase, delete the
committed value at line 50 of `.env` and the placeholder at line 40. Commit the fix
with a clear message.

## 5. Application-layer security — open items

These are not secrets but are security-relevant and surfaced during audit:

1. **CORS** — `.env.local` widens CORS to `192.168.*.*`, `100.*.*.*`, and
   `lightskyblue-turtle-221397.hostingersite.com`. Production CORS must not include
   private network ranges unless explicitly needed for APK dev.
2. **Mass assignment** — Doctrine setters are explicit (good). Spot-check controllers
   for `$entity->setX($request->request->get('x'))` patterns during `F4 Integrate`.
3. **SQL injection** — Doctrine ORM parametrized queries (low risk). Verify
   `EntityManager::createNativeQuery` usage (currently appears none).
4. **XSS** — Twig autoescape is on by default. Verify any `|raw` usage during
   `F2 Design System` audit.
5. **CSRF** — Stimulus controllers in `assets/controllers/` include `csrf_protection`.
   Verify it covers all POST endpoints (especially `SyncController` and
   `ChatUploadController`).
6. **JWT refresh** — `Auth/RefreshTokenService` exists. Verify rotation, revocation
   list and TTL during `F10 Security` deep dive.
7. **Rate limiter** — `RateLimiterService` exists. Verify it's wired into
   `/api/auth/login`, `/api/chat/*`, `/api/upload/*`.
8. **Authorization** — Many controllers check `$this->getUser()` only. Verify role
   gates (`ROLE_ADMIN`, `ROLE_MENTOR`) on every privileged endpoint.

- **No `var/data_*.db` in commits, zips, or external storage.**
- **No `stitch_tnsvt_app_m_vil/` in commits once consolidated.**
- **Every rotation must update both the secret store AND any consumer config
  (Firebase rules, Mercure hub, MySQL grants).**
- **Audit log writes** are already implemented (`AdminAuditLogger`). Verify it's
  invoked on auth and admin actions.
