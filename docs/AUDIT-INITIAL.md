## 10. Guardian — pieces already in the repo

Although there is no `GuardianService` or `GuardianController`, the architectural
*atoms* of Guardian already exist:

| Atom | Where | Role |
|---|---|---|
| `PropFirmAlert` entity | `src/Entity/PropFirmAlert.php` | Typed risk alerts (drawdown, daily loss, profit target, violation) with severity |
| `PropFirmAccount` entity | `src/Entity/PropFirmAccount.php` | Account with `getDrawdownPct()`, `getProfitPct()` derived methods |
| `PropFirmRuleChecker` service | `src/Service/PropFirmRuleChecker.php` | Rule engine for prop firm compliance |
| `NoTradeWindowService` | `src/Service/Macro/NoTradeWindowService.php` | Macro-level "no trade" windows |
| `MonitoringService` | `src/Service/Monitoring/MonitoringService.php` | Event capture + alert routing |
| `DiaryEntry` entity | `src/Entity/DiaryEntry.php` | Encrypted psych state (input) |
| `JournalEntry` entity | `src/Entity/JournalEntry.php` | Trade journal (input) |
| `Notification` entity | `src/Entity/Notification.php` | Output channel |
| `PushService` / `PushNotificationService` | `src/Service/...` | Delivery channel |
| `OracleMetricsService` | `src/Service/Oracle/OracleMetricsService.php` | Could feed Guardian with metrics |

**Gap (this is the consolidation opportunity):**

- No unified **Guardian interface** that orchestrates the above.
- No **behavior / discipline score** derived from `DiaryEntry` + `JournalEntry`.
- No **soft warning before violation** — current `PropFirmAlert` is post-event.
- No **mentor feedback loop** — no `MentorController`, no mentor role on `User`.
- No **cross-domain correlation** (e.g., diary mood × trade performance × macro
  events).
- No **Guardian dashboard / Sanctum view** in the navigation.

This is documented for `F4 Integrate` phase — see `INFORMATION-ARCHITECTURE.md`
§Mind & Macro.
